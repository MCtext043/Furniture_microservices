# Отчёт: продакшн-готовность Петров

Дата: 20.09.2026

## 1. Ценообразование 3D-проектов из раскроя

Стоимость больше не считается только по площади деталей. Планировщик вызывает `POST /cutting/quote` — тот же оптимизатор, что и производственный раскрой, но без сохранения задания.

- В расчёт идут **целые листы** (`total_sheets × площадь листа × цена м² ЛДСП`).
- Кромка считается по контуру деталей из BOM.
- Комплектации Стандарт / Комфорт / Премиум строятся от закупочной суммы и конструктора фурнитуры.
- При отправке в работу в CRM уходит число листов и материалы, созданные из раскроя (не из демо-справочника).

Проверка: `tests/common/test_pricing.py`, `tests/cutting/test_cutting_api.py::test_quote_does_not_save_job`.
    
## 2. Работа без тестовых данных CRM

Проект больше не зависит от кнопки «Загрузить демо CRM».

- `POST /catalog/crm/seed-demo` отключён (HTTP 410).
- Автозагрузка демо-каталога и демо-мебели в 3D отключена.
- Материалы заказа создаются при отправке проекта (`material_name` + количество листов).
- Пустой склад — нормальное стартовое состояние; закупка считается от потребности заказа.

Проверка: `test_submit_project_creates_materials_from_names`, `test_submit_project_uses_cutting_when_materials_omitted`.

## 3. Данные не «из воздуха»

- Цены проекта: раскрой + ставки материалов, не случайные константы карточек.
- Заказы CRM: только реальные отправки из планировщика или ручное создание админом.
- Каталог: только товары, которые добавил администратор.
- Складской адрес по умолчанию пустой, без фиктивного «ул. Складская».
- Демо-кнопки каталога и CRM убраны из админки.

## 4. Календарь заказов (UTC+4)

В админке секция **Календарь**.

- Часовой пояс: `Asia/Dubai` (UTC+4 без летнего времени).
- Заказ стоит на дате `status_changed_at`. Создание — сегодня; смена статуса через неделю переносит карточку на новую дату.
- Desktop: сетка месяца. Mobile: список дней.
- Клик по заказу открывает карточку (статус, материалы, закупка, фото, чеки).

Проверка: `test_status_change_moves_calendar_timestamp`.

## 5. Главный администратор и сотрудники

Главный админ — учётка из `.env` (`AUTH_BOOTSTRAP_USERNAME` / `PASSWORD`), роль `superadmin`.

- Раздел «Админы» виден только главному.
- Можно задать логин и пароль, опционально почту.
- Если SMTP настроен, сотруднику уходит письмо со ссылкой `/auth/verify-email?token=...`.
- Сотрудник получает права записи (каталог, CRM, раскрой, файлы), **без удаления**.
- Удалять заказы, товары, категории, историю раскроя и других админов может только `superadmin`.
- Главного администратора удалить нельзя.

## 6. Безопасность

- JWT: `admin` больше не равен полному доступу к DELETE; удаление только у `superadmin`.
- CORS шлюза ограничен localhost/явно заданным `GATEWAY_CORS_ORIGINS` (раньше принимал любой origin).
- Заголовки: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Логин: не больше 8 попыток в минуту с одного IP+логина.
- Пароли: bcrypt. Токены подтверждения почты хранятся как SHA-256.
- HTTP DELETE защищён `ensure_can_delete` (кроме корзины/избранного клиента).
- Скрытие товара для сотрудников — `PATCH is_active=false`, не удаление.

Для продакшена обязательно сильные `JWT_SECRET_KEY`, `AUTH_BOOTSTRAP_PASSWORD`, SMTP и `PUBLIC_APP_URL`.

## 7. Как проверить вручную

1. Применить миграции (`012_production_ops`) и перезапустить сервисы.
2. Войти в `admin.html` учётом из `.env`.
3. Создать второго админа, войти им: кнопки «Удалить заказ» и «Очистить историю раскроя» скрыты, API DELETE отвечает 403.
4. На витрине собрать 3D-проект (без демо-набора), выбрать комплектацию, отправить в работу **без** загрузки демо CRM.
5. В CRM появляется заказ с листами из раскроя; в календаре — на сегодняшней дате UTC+4.
6. Сменить статус — карточка переезжает на новую дату; клик открывает заказ.

Автотесты: `pytest tests/common tests/catalog/test_crm_workflow.py tests/cutting tests/auth`.
