# Уведомления о заказах

Новые заказы из клиентского планировщика и созданные через `/crm/orders` автоматически ставятся в очередь отправки на `petrov_mebel@mail.ru`. Письмо содержит HTML-оформление, текстовую версию, контакты клиента, выбранную комплектацию, предварительную стоимость, материалы и примечания.

## Настройка

Отправка выполняется через Яндекс Почту или Яндекс 360. Письма уходят с вашего ящика в Яндексе на `petrov_mebel@mail.ru`. Укажите реальный адрес своего ящика вместо `your-mailbox@yandex.ru`.

1. В Яндекс Почте откройте **Настройки → Все настройки → Почтовые программы**, разрешите доступ по IMAP и использование паролей приложений и OAuth-токенов.
2. В Яндекс ID создайте пароль приложения для почты и используйте его в `SMTP_PASSWORD`.
3. Для Яндекс 360 с собственным доменом укажите полный адрес корпоративного ящика в `SMTP_USER`.

Официальная инструкция: [настройка почтовых клиентов Яндекса](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

В файле окружения, используемом при запуске Docker Compose (`.env`, `.env.server` или `deploy/local.env` для соответствующего способа деплоя), задайте:

```dotenv
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURITY=ssl
SMTP_USER=your-mailbox@yandex.ru
SMTP_PASSWORD=пароль_приложения_почтового_ящика
SMTP_FROM=
```

Пустой `SMTP_FROM` означает отправку от адреса `SMTP_USER`. Для Яндекса адрес отправителя должен соответствовать авторизованному ящику или разрешённому для него адресу. `petrov_mebel@mail.ru` используется как получатель, а не как логин Яндекса.

Используйте пароль приложения почтового ящика. Не добавляйте его в Git. Получатель зафиксирован на сервере, клиент не может его изменить. Для другого SMTP-провайдера задайте его хост, пользователя, отправителя и при необходимости `SMTP_SECURITY=starttls`, `SMTP_PORT=587`.

Примените миграции и пересоздайте `catalog-service` с новыми переменными окружения. Для серверного Compose:

```sh
docker compose --env-file .env.server -f docker-compose.server.yml run --rm migrate
docker compose --env-file .env.server -f docker-compose.server.yml up -d --build catalog-service
```

Очередь сохраняется в БД вместе с заказом. Без SMTP-реквизитов письма остаются в очереди; после настройки и перезапуска сервиса они будут отправлены. При ошибке доставки повтор выполняется через 1 минуту с увеличением интервала до часа. Успешная отправка отмечается в `order_email_outbox.sent_at`. Отправка выполняется в фоне и не задерживает оформление заказа. При аварии между приёмом письма SMTP-сервером и фиксацией результата в БД возможна повторная доставка.

Демонстрационные записи, созданные сидером, и сохранённые без отправки в работу проекты не отправляются. Ранее существовавшие заказы автоматически не рассылались и не ставятся в очередь при обновлении.
